## 0. Идея в одном абзаце

Платный — только удалённый исполнитель. Всё, что можно сделать локально (бесплатно),
делается **до** платного запроса: локальная модель (3B–31B из списка локальных моделей
пользователя) получает доску кандидатов проекта и **собирает атомарную задачу** —
без написания кода, только с названиями функций/переменных. Хост материализует
названные куски кода в один большой точечный промпт и отправляет его удалённой модели
**одним запросом**. Так сокращаются платные раунды (а не локальные), а удалённая
мель получает содержимое, а не список файлов для чтения.

## 1. Зафиксированные решения владельца продукта

| # | Решение | Следствие в коде |
|---|---|---|
| D1 | Перед отправкой показывать лоадер «собираем точечный контекст» | новое состояние `isCompilingContext`, отдельное от `isLoading` |
| D2 | Под каждым отправленным сообщением — кнопка показать **полный** собранный контекст (без сводки) | новая часть сообщения `compiledContext` + sheet-просмотрщик |
| D3 | Локальная модель: из списка внутренних моделей пользователя, «как есть», ≥3B; если модель не ответила — берётся следующая в списке | `LocalModelDirectory` поверх `LocalProviderConfig.models` |
| D4 | Никаких фолбэков и заглушек: JSON проверяется на синтаксис; пустой/битый ответ — явная ошибка пользователю, отправка не выполняется | `LocalTaskCompilerService` бросает/возвращает типизированную ошибку |
| D5 | Единственное ограничение объёма — окно удалённой модели; при превышении — разбивка на чанки с пометкой «часть i/n» | `PromptChunker` + маршрутные правила отправки |
| D6 | Web/ACP/serve-маршруты: чанки отправляются **последовательными платными запросами**, с явным объяснением модели, что нужно дождаться всех чанков | `ChunkedSendSequencer` + текст-объяснение в первом сообщении |
| D7 | Локальная модель **не пишет код**: только называет функции/переменные и собирает атомарную задачу | контракт `refs` (path/symbol/lines), запрет на поля с кодом |
| D8 | Лимита на количество файлов в контексте нет | ограничение только окно удалённой модели |
| D9 | Очередь не останавливает текущую работу; контекст собирается **в момент отправки** (включая принудительную отправку) | компиляция внутри `sendDirectly`, не в `enqueue` |
| D10 | Формат атомарной задачи свободный (JSON или mixed), важна понятность для модели | валидируем JSON, но поддерживаем свободный текст с разбором `path:line` |
| D11 | После выполнения задачи — локальная критика («адвокат дьявола»): ≥95 и без блокирующих замечаний → прогресс в локальном TODO; ниже → «лучшее решение» | Stage H |

## 3. Контракты

### 3.1 Ответ локальной модели (валидируемый JSON)

```json
{
  "atomicTask": "Что именно сделать — 1–3 предложения, без кода",
  "tdd": {
    "required": true,
    "steps": ["1) падающий тест X", "2) прогон (красный)", "3) реализация", "4) прогон (зелёный)"]
  },
  "acceptance": ["проверяемый критерий 1", "..."],
  "refs": [
    {
      "path": "myCoder/Sources/Services/ProjectWebToolExecutor.swift",
      "symbol": "grep(pattern:in:)",
      "startLine": 683,
      "endLine": 720,
      "why": "место полного перескана"
    }
  ],
  "knownGaps": ["тестов на стабильность нет"]
}
```

Обязательные поля: `atomicTask` (непустая строка), `refs` (массив; может быть пустым —
тогда удалённая модель дозапросит код сама). Опциональные: `tdd`, `acceptance`,
`knownGaps`. Любой `ref.path` обязан существовать в индексе проекта — иначе ошибка
(«ссылка не найдена»), а не молчаливое отбрасывание.

### 3.2 Правила валидации (без фолбэков)

1. Синтаксис: `JSONSerialization.jsonObject`; ошибка → `LocalCompilerError.invalidJSON(описание, сырой текст)`.
2. Обязательные поля: отсутствие/пустота → `LocalCompilerError.missingField(...)`.
3. Ссылки: `path` не найден в индексе → `LocalCompilerError.unknownReference(path)`.
4. Пустой `refs` — валидный случай: задача уходит без кода.
5. Любая ошибка → сообщение в чат (`⚠️ Не удалось собрать контекст: …`), удалённый запрос **не** выполняется.

### 3.3 Формат собранного контекста (то, что уходит модели)

```
<project-context kind="task" project="/path" bytes="48210/200000" fresh="2 min ago">
## Атомарная задача
<atomicTask>

## TDD-контракт
1) ...

## Критерии приёмки
- ...

## Код
### myCoder/Sources/Services/ProjectWebToolExecutor.swift:683-720 (grep(pattern:in:))
<выдержка>

## Чего не знаем
- ...
</project-context>
```

## 6. Риски и контрмеры

| Риск | Контрмера |
|---|---|
| Локальная модель ответит не-JSON | D4: явная ошибка + разбор `path:line`; никаких молчаливых заглушек |
| Локальная модель недоступна | D3: следующая модель в списке; если нет ни одной — ошибка в чат (видно пользователю) |
| Сборка контекста дольше, чем пользователь готов ждать | Лоадер с описанием этапа; замер времени сборки в логе/метриках |
| Промпт не влезает в окно удалённой модели | `PromptChunker` + последовательные запросы для web-маршрутов (D6) |
| Локальная модель начнёт писать код | D7: в контракте нет места для кода; лишние поля отбрасываются валидатором |
| Двойная оплата при последовательных чанках | Для OpenAI-совместимых — один запрос с несколькими сообщениями; для web — по требованию владельца |
| Контекст устарел между сборкой и отправкой | Сборка непосредственно перед отправкой; в пакете указывается время сборки |

## 7. Метрики (после Stage D)

- платные раунды на типовую задачу (было/стало);
- размер собранного контекста (байты) и число файлов;
- доля запросов, где собранный контекст непустой;
- время локальной сборки контекста (мс);
- доля задач, закрытых с первого платного раунда.

## 8. Ограничения окружения

Swift-тулчейн в среде разработки отсутствует (сборка требует macOS), поэтому код
проверяется чтением и ревью; `swift test` и `./build-app.sh` запускаются владельцем
на macOS. Каждый этап обязан быть завершён вместе с тестом, иначе этап не закрыт.
