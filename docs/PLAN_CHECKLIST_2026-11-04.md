## Раунд 2 — гейт качества «адвокат дьявола» (⬜)

Задумка владельца: после полного ответа большой модели внутренняя модель
оценивает качество выполнения как адвокат дьявола. Оценка < 95 и план не
выполнен, а пользователь приказал «не останавливаться, пока план не выполнен» →
в модель автоматически уходит разбор качества + напоминание, что команды
останавливаться не было. Стоп — только если вмешательство пользователя
критически необходимо.

- ⬜ R2.1 Красный тест чистой логики `AnswerQualityGate`:
      - детект приказа «не останавливайся» в тексте пользователя (RU/EN cues);
      - парсинг вердикта (JSON: score 0-100, findings, missing, requiresUser);
      - решение: `accept` (≥95 или план готов) / `continueTurn(feedback)`
        (<95 + план не готов + приказ) / `askUser` (requiresUser);
      - текст авто-продолжения несёт разбор + «команды останавливаться не было».
- ⬜ R2.2 Красный тест раннера: внутренняя модель получает промпт ревьюера;
      нет назначенной модели → гейт честно пропускается (не выдумывает оценку).
- ⬜ R2.3 Красный wiring-тест (source-scan): ход завершён → гейт вызывается;
      решение `continueTurn` → авто-отправка фидбека в ту же сессию с лимитом
      глубины (защита от бесконечного цикла); вердикт виден в чате
      (служебное сообщение с оценкой) и в стадии сбора.
- ⬜ R2.4 Реализация: `AnswerQualityGate.swift` (чистая логика),
      интеграция в `sendDirectly` (обёртка после хода), авто-продолжение
      с параметром глубины, план-состояние из `PlanTodoBridge.planItems`.
- ⬜ R2.5 Батч-прогон; гейт ≥95; коммит + пуш.
