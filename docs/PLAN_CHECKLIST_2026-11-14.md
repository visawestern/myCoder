## Раунд 2: аудит «адвоката дьявола» — 15+ дефектов

Проверка каждого пункта против ожидаемого результата выявила следующие
реальные дефекты (не косметика):

### Пункт 1 (рендер-кэш)
1. **Стриминг кэшируется.** `MessageRowView.renderedKey` не проверяет
   `message.isStreaming`, поэтому промежуточные тексты ответа попадают в
   кэш и закрепляются. Исправление: `RenderedMessageCacheLogic.shouldCache`
   + guard в `renderedKey`. (TDD: `streamingIsNotCached` — добавлен.)
2. **`RenderedTextViewPool` без лимита.** Пул может хранить view сверх
   любых лимитов пар (память). Исправление: лимит пула (512 view суммарно)
   с вытеснением самых старых.
3. **`RenderedMessageStore.row` не отмечает обращение (LRU).** В отличие от
   `record(for:)`, обычное чтение строки не вызывает `recordAccess`, поэтому
   горячий чат может быть вытеснен при глобальном переполнении.
   Исправление: вызывать `recordAccess` при попадании в `row`.
4. **`CodeHighlightKey.language` не нормализуется.** `swift` и `Swift` —
   разные ключи кэша подсветки. Исправление: нижний регистр + трим.
5. **`resetHighlightCache` не вызывается при смене темы.** Старые записи
   с недостижимыми палитрами держатся до лимита. Исправление: вызов при
   смене темы.
6. **`row` делает `insert` на каждый запрос**, даже когда пара уже есть
   (лишняя работа и перезапись state).

### Пункт 2 (спойлеры)
7. **Нет анимации раскрытия/сворачивания** (была убрана). Лёгкая
   анимация opacity+move не ломает переключение чатов.
8. **`GoalsSection` использует `titleSize: 12`**, а остальные секции — 14:
   визуальная несогласованность заголовков.

### Пункт 3 (web_search)
9. **Нет лимита размера HTTP-ответа** — страница DDG может быть огромной;
   нужен cap (например, 1 МБ) и честное сообщение при превышении.
10. **Снипеты не обрезаются** — результат может раздуть контекст;
    нужна обрезка снипетов (240 симв.) в рендере.
11. **HTTP 202/429/503** обрабатываются одинаково («HTTP N») — для 429
    стоит вернуть понятное «слишком много запросов, повторите позже».

### Пункт 4 (кликабельные пути)
12. **`ChatFileLinkLogic.path(fromLink:)` не учитывает host** в схеме
    `mycoder-file://host/path` (неоднозначность). Добавить отклонение
    непустого host.
13. **Курсор-палец добавляется только для `.chatFilePath`**, а не для
    `.link` своей схемы (если атрибут chatFilePath отсутствует). Добавить
    enumerate по `.link` в `resetCursorRects`.

### Пункт 5 (пул ключей)
14. **Изменение текста ключа сохраняется только по Enter/кнопкам** —
    `TextField` не имеет `.onChange`, поэтому потеря фокуса без Enter теряла
    ввод. Исправление: `.onChange` строки → onCommit.
15. **Синхронизация поля основного ключа**: при переключении провайдера
    `loadProviderDrafts` строит `fullList` заново — поле сверху может
    показывать устаревшее значение (editValue обновляется только при
    загрузке). Проверить и подтянуть.
