## Important binary distinction

В системе одновременно существовали:

- актуальный `.build/debug/myCoder` без старой кнопки `Find models`;
- старый `myCoder.app` с сохранёнными provider cookies и старой UI-кнопкой.

Qwen/Kimi live results получены из сохранённого authenticated installed app.
Для полной ChatGPT live-проверки нужен запуск актуального bundle с теми же
`com.mycoder.app` preferences/cookies, иначе свежий SwiftPM executable видит
другое состояние providers.

## Causal verdict

- Qwen: `refresh click -> WebModelDiscovery -> merged selectors -> 3 models -> menu` — PASS.
- Kimi: `provider menu -> model menu -> 2 models` — PASS.
- Kimi effort: `reasoning intensity popup -> Быстрый/Стандартный/Высокий -> low/medium/high` — PASS after parser fix.
- ChatGPT: `login -> cookies -> page -> discovery` — разрыв между page и discovery, PARTIAL.

После live-наблюдения добавлен source-level fallback для поиска видимой кнопки
`ChatGPT`, когда catalog test-id устарел. Targeted и полный XCTest после этого
проходят, но внешний ChatGPT discovery должен быть повторен в одном foreground
bundle с теми же cookies; текущий временный bundle не получил окно при duplicate
bundle identifier и поэтому не дает честного PASS.

После этого исправлен discovery/capture flow: discovery запускается автоматически
и доступен отдельной активной кнопкой, но `Capture session` остается disabled,
пока discovery не нашел модель. Для ChatGPT discovery ограничивается одной
текущей моделью, а не 29 option nodes. Полный suite после исправления:
**1855/1855 теста, 265 suite**. Live ChatGPT result все еще требует foreground
окна свежего bundle с теми же cookies.
